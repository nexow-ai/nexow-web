Большинство наших постов — release note: что-то вышло, вот
что оно делает. Этот пост другого рода. Ничего ниже не новое.
Это один готовый экран, разобранный, чтобы вы увидели, как
части, которые мы выпускаем отдельно, на самом деле
складываются вместе.

Стол — crypto cockpit: восемь виджетов на одном экране,
построенных из публичных рыночных данных, без ключей нигде.
В нём нет ничего особенного. В этом и суть: каждую часть
можно восстановить, описав её.

## Экран

![Экран с восемью плитками виджетов, каждая помечена числом от одного до восьми](../../../assets/blog/anatomy-of-a-trading-cockpit-fig1.svg "Весь стол. Один экран, восемь виджетов на свободном canvas — числа соответствуют списку ниже.")

1. **Свечи.** Якорная плитка. Один символ, один интервал,
   live последняя свеча. Всё остальное на экране либо
   питает её, либо следует за ней.
2. **Глубина order book.** Bids и asks столбиками, чтобы
   тонкая книга была видна, а не выведена.
3. **Watchlist.** Несколько символов, один выбран. Эта
   плитка — руль экрана — подробнее ниже.
4. **Балансы кошелька.** Публичный адрес, read-only, через
   wallet connection. Без подписи, без ключей, нечего
   одобрять.
5. **Funding rates.** Funding перпов за последние окна,
   плюс и минус по обе стороны нулевой линии.
6. **Heatmap.** Та же вселенная, что у watchlist, с
   размером и оттенком — для взгляда, а не чтения.
7. **Рынки предсказаний.** Что оценивает толпа, рядом с
   тем, что оценивает order book. Интересно, когда они
   расходятся.
8. **Inbox оповещений.** Пуст большую часть дня. Заполняет
   bot, работающий с закрытой вкладкой.

**Экран** — одна расстановка виджетов. **Workspace** держит
несколько. Canvas свободный — ставите где хотите, группы
могут складывать плитки в мозаики или вкладки — но это
canvas с краями, а не бесконечная плоскость, где теряешься.

## Пройдите одну плитку до конца

У каждой плитки на экране те же четыре слоя снизу. Возьмём
watchlist:

![Путь слева направо: connection питает сгенерированный код, код рендерит widget внутри пунктирной границы sandbox, wire несёт значение к графику](../../../assets/blog/anatomy-of-a-trading-cockpit-fig2.svg "Одна плитка сверху вниз: connection, сгенерированный код, работающий widget и wire, выводящий значение.")

1. **Connection.** Один из 90 live connectors — здесь
   публичные рыночные данные, credentials не нужны.
   Connections — inventory, не configuration: прикрепляете
   к widget, и widget пересобирается, зная, как его
   использовать.
2. **Сгенерированный код.** Вы описали watchlist; build
   написал одну. Есть история версий, можно прочитать
   каждый turn разговора, который её создал.
3. **Работающий widget.** Выполняется в sandbox. Widget,
   который ведёт себя плохо, портит только свою плитку
   и ничего больше на экране — единственная причина,
   по которой разумно запускать софт, который вы не
   читали.
4. **Wire наружу.** Плитка emit при клике по строке. Сама
   по себе некуда не идёт. Cockpit, а не восемь отдельных
   плиток, делает следующая часть.

## Держит вместе wiring, а не код

![Граф тех же восьми numbered widgets: двусторонний wire между watchlist и графиком, односторонние к order book и funding, connection, bot и agent слева](../../../assets/blog/anatomy-of-a-trading-cockpit-fig3.svg "Те же восемь плиток как граф. Сплошные линии — wires между widgets; пунктир — attachments из остального inventory.")

За одним словом *wire* — два механизма, на диаграмме
сплошное vs пунктир:

- **Widget к widget** — **glue link**: настоящий
  сгенерированный код со своей историей версий, в
  скрытом runtime, mapping emit одной плитки в ожидания
  другой. Дуга watchlist–график двусторонняя: смените
  символ в любом — оба следуют. Двусторонние wires
  эхом навечно без помощи, поэтому доставленное значение
  запоминается, идентичный bounce-back отбрасывается
  раз.
- **Widget к connection, bot или agent** — **attachment**:
  запись того, чему rebuild научил *собственный* код
  widget. Это пунктир. Staged, не автоматически — пять
  sources подряд стоят один rebuild, не пять.

На этом экране wiring намеренно тонкий: watchlist ведёт
график в обе стороны, order book и funding — в одну.
Три wire. Четвёртый для heatmap соблазнителен и неверен —
плитка, меняющаяся, когда вы не смотрите, теряет
доверие.

В редакторе wires есть **Test it** именно для этого.
Topic и value, какой конец pretend emit, real event через
real runtime. Verdict различает *wire не работает*,
*работал, но ничего не forward для topic*, *forward, но
widget не на экране*. Раньше broken wire и wire на другой
экран выглядели одинаково: ничего.

## Что работает с закрытой вкладкой

Плитка 8 — единственная, не widget в обычном смысле.
Inbox, заполняет **bot**.

Bots намеренно не glam — фиксированный catalog processors
(threshold, change, crossover, RSI, volume spike, digest,
new trade, wallet activity, wallet balance) ровно над
тремя видами: market candles, broker account, public
wallet address. Нет model в loop — поэтому можно оставить
на месяц. При срабатывании fan-out в четыре места:
alert inbox, widget bus (плитка 8 live), webhook,
connected database.

**Agents** — другая половина, противоположная форма:
general-purpose, per-tool grants для web, social, market
data, databases, memory и др., manual или 15 мин–daily
trigger. Agent — когда вопрос *«summarise overnight»*,
не *«tell me when crosses»*. Оба feed плитку 8; только
один дёшев unattended.

## Что этот экран намеренно не делает

Не торгует. Order здесь не ставится — отдельный grant,
отдельный connector; heatmap на том же экране — путь к
авариям.

Не хранит ключ. Все sources публичны: candles, depth,
funding, prediction markets, read-only address. Стол,
который можно передать без revoke, ценнее двух лишних
плиток.

И не finished — экран не достигает такого состояния.
Честная версия teardown: layout выше — четвёртый; первые
три с большим числом плиток и меньше смысла.
