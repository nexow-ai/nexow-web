生成ウィジェットが失敗する最も一般的な理由は、生成コードのバグではありませんでした。
存在しなかった endpoint でした。

モデルは記憶の URL——またはリンクが *ドキュメントページ* で endpoint ではない
ディレクトリ行——から推測し、レスポンス形状を当て、当てに parsing を書き、
出荷しました。永遠のスピナーか空チャート、画面に理由はありません。

本リリースは3段でループを閉じます：書き中、書いた直後、目の前でまだクラッシュ
するならもう一度。

## 書き中：`probe_url`

builder に **今すぐ keyless 公開 endpoint を GET** するツール——runtime の
`ctx.data.http()` と同一サーバープロキシ経由——本物の HTTP ステータスと body を
返します。

その同一性が要点。成功 probe *は* 成功 runtime 呼び出し。失敗 probe は壊れたまま
出荷されるウィジェット——修正ターンが残る今失敗し、キャンバスではない。

builder は記憶で推論せず辿るはしごの底にあります：venue 参照ドキュメント、次に
**691 keyless 公開 API・47カテゴリのディレクトリ**、各エントリの名前 *と*
説明を topic 検索——「潮汐」「大気質」は当てのカテゴリにマップしにくい。
常に builder に利用可能——universal keyless fallback。リンクはドキュメントなので
最終段階は常に同じ：endpoint を導出し probe。

「X のデータはあるか」は推論ではなく見て答える。はしごの底で本当に確認して
*いいえ* は良い結果。記憶で断言は良くない——感じよりずっと多く外していた。

## 直後：検証器

自分の仕事を検証させるのは依頼であり保証ではない。コードが着地した瞬間、
モデルの同意なしに2つ：

第一、ツール結果が **このターン probe しなかった endpoint を名指し**、
残りラウンドで確認するよう指示。

第二——協力に頼らない部分——検証器が **モデルが要約を書くのと並行** 実行し
自ら作業：

- **モジュール lint**——構造上静かな失敗クラス。`render` export 欠落。パース不能。
  サードパーティ host への raw `fetch`/`WebSocket`（sandbox ブロック）——生成
  ウィジェット最大の静かな被害、コンソールに何も出ない。外部画像/動画 URL を
  `src` へ直接。map ライブラリへ hardcode tile URL——マウントとパンは完璧、
  タイル要求は静かに拒否。
- **モデルがスキップした endpoint を probe**（モジュール最大5）、モデルと同様に
  判定：到達不能、または URL/パラメータ誤りを示す 4xx。

実問題は **in-turn 自動修復1ラウンド**——probe 出力を証拠に、指摘のみ修正。
build 全コンテキストがまだ熱いうち——壊して後から全ターンより安い。途中で
モジュール書き換えなら実行中検証は supersede され判定破棄。内部失敗した
検証器は clean 判定——build を遅らせるだけ、壊さない。

## まだクラッシュ：1回、厳格に上限

自己修復コンテキストは runtime エラーを *次* チャットターンへ——送信時のみ。
build 数秒後クラッシュは、気づき composer を開き「壊れてる」と打つまで壊れたまま。

runtime ホストは fresh build クラッシュで **自動 fix ターン1回**。自動ターンは
クレジットかキーを消費——境界は意図的に厳しい：

- AI build が *今* 出したバージョンのみ——復元した旧版や手編集コードのクラッシュは
  対象外；
- その build から **45秒以内**——1時間後のクラッシュはあなたにとって新情報；
- **バージョン1回**、auto-repair ターンが生んだ版は再対象外。1 build が触れる
  自動 follow-up は最大1——モデルが自分に課金して失敗し続ける連鎖は never。

修復ターンはアプリが欠陥報告する体裁。上と同じ指示：データ endpoint 絡みなら
書き換え前に probe。直す、動くものは残す、スコープを広げない。

サーバー側、救済 background build は同一ウィジェットの別ターンが live なら
待機——重複版へ競合しない。

## 同一ループ、全モード

すべて共有モジュール——プラットフォーム build、ブラウザ BYOK、サーバー sweep が
**同一** 振る舞い：同ツール、同 probe 形式、同検証器、同修復予算。モードは
ツール存在や厳格度で乖離できない——答えの実装は1つ。[次リリース同梱の10
サンプル](/blog/starter-widgets-examples-workspace) もこのループ、これらの
チェックで build。

いずれもモデルを正しくはしない。誤りを生き延びさせ、通常は不可視に：コードが
依存する前に endpoint 確認、モデルの気分に関わらずチェック実行、最初のクラッシュに
到達前の正直な fix 試行1回。

前に activity rail が endpoint を probe するのを見てください。
