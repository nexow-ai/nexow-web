Il y a quelques semaines, nous annoncions l’arrivée des agents : une IA dotée
d’un harnais complet qui surveille, raisonne et agit d’elle-même. Aujourd’hui,
ils sont là. Vous pouvez construire un agent, lui confier des outils, le
**déployer dans le cloud** et le regarder travailler — selon un planning,
onglet fermé.

Voici ce qui vient de sortir.

## Le harnais, désormais avec un bouton Déployer

Un agent dans Nexow, c’est plus qu’un prompt. Vous l’assemblez à partir d’un
**harnais** — modèle, mémoire, skills, outils, connaissances et triggers —
dans un builder visuel. Cette partie, vous l’avez peut-être déjà vue. La
nouveauté, c’est la dernière étape : **Déployer**.

Le déploiement prend un instantané de votre agent et le confie au runtime
cloud de Nexow. À partir de là, il tourne sur son propre heartbeat — toutes
les 15 minutes, toutes les heures, tous les jours, la cadence que vous voulez
— sans que votre navigateur soit ouvert. Vous pouvez aussi le solliciter
manuellement avec **Exécuter maintenant** quand vous voulez un passage hors
planning.

## Les outils s’accordent, ils ne vont pas de soi

Un agent ne touche que ce que vous le laissez toucher. Chaque outil de son
harnais est **soumis à autorisation** : vous décidez s’il peut lire vos
connexions, publier des notifications, écrire dans vos widgets, et ainsi de
suite. Pas d’autorisation, pas d’accès — l’agent ne voit littéralement pas
l’outil.

C’est ce qui permet de confier à un agent un vrai travail en toute sécurité.
Un bot vous dit que BTC a chuté de 5 % ; à un agent, vous pouvez demander *de
vérifier le carnet d’ordres et le funding rate quand ça arrive, et de rédiger
ce qu’il a trouvé* — avec exactement les accès que vous avez validés.

## De la mémoire entre les runs

Les agents gardent une **mémoire** d’un run à l’autre. Ce que votre agent a
appris lors du passage de lundi est encore là mardi — il peut donc suivre une
thèse dans le temps, remarquer les changements au lieu de redécrire des
instantanés, et s’épargner le travail déjà fait.

## Chaque run, consigné

Les agents déployés tiennent une **timeline des runs** : quand chaque run a
démarré, s’il s’est terminé proprement, a échoué ou a été sauté, et ce qui
s’est passé à l’intérieur — diffusé en direct pendant l’exécution. Ouvrez
n’importe quel run pour lire la conversation complète : ce que l’agent a vu,
quels outils il a appelés et ce qu’il a conclu. Si un modèle en amont a un
raté, cela atterrit aussi dans l’historique, étiqueté pour ce que c’est, pas
comme un mystère.

Vous gardez la main du début à la fin : mettez un agent en **pause**,
**reprenez-le**, redéployez un harnais mis à jour ou **retirez-le du cloud**
entièrement. Votre plan détermine combien d’agents vous pouvez garder
déployés à la fois.

## Toujours privé par défaut

Le principe n’a pas bougé : le cloud est un choix auquel vous adhérez.
Construire un harnais ne coûte rien et ne touche aucun serveur ; le
déploiement est une décision explicite par agent, et le mode privé met les
runs cloud en pause au lieu de les poursuivre discrètement.
